# improve-skill

## 入力

- 最新の振り返りファイル (`docs/retrospectives/`)

## 手順

1. 最新の振り返りファイルを読み込み、Try に記録された改善対象を特定する
2. 対象となるスキル定義ファイル (`docs/skills/`) を読み込む
3. 既存の規約との整合性を確認する
4. 改善案 (新しい SKILL.md の内容) を作成する
5. 改善案に対して `eval-skill` を実行し、評価を受ける
6. 評価結果に基づく採否判定:
    - **PASS**: 改善案を適用し、現在の変更内容（git diff）を確認して、わかりやすいPRのタイトルと説明文を考えてください。その後、gh コマンドを使って dev ブランチへのプルリクエストを作成してください (dev へのマージは自動)
    - **FAIL**: 改善案を破棄し、再度改善を検討するか、現在のスキルを維持する
7. 改善が採用された場合は、改善内容を記録する

## 改善の原則

- 過去の問題を再発させない
- 既存の正常な動作を壊さない
- 個別タスク固有の事情を安易に一般ルール化しない
- 改善内容は具体的かつ再現可能なものにする
- 禁止事項や重要な制約は、エージェントが見落としにくい位置に配置する
