# tdd-implement スキル テストケース

このドキュメントは、`tdd-implement` スキルが設計通りのワークフロー（TDD -> 実装 -> 品質ガード -> retro）を実行できるか検証するためのテストシナリオを定義します。

## テスト環境の前提条件
- `go` がインストールされていること。
- `golangci-lint` がインストールされていること。
- `retro` スキルが利用可能であること。

## テストシナリオ

### 1. 正常系: 基本的な数学ユーティリティの実装
- **目的**: 最もシンプルなケースで TDD サイクルが回るかを確認する。
- **入力 (specification)**:
    - 「2つの整数を加算する `Add` 関数を `pkg/mathutil` パッケージに実装してください。入力は `int` 型、出力は `int` 型です。」
- **入力 (target_path)**: `pkg/mathutil/add.go`
- **期待される挙動**:
    1. `pkg/mathutil/add_test.go` が作成され、テストが失敗する。
    2. `pkg/mathutil/add.go` に実装が追加され、テストがパスする。
    3. `go fmt` および `golangci-lint` がパスする。
    4. `retro` が呼び出される。
- **合格基準 (PASS)**: すべての手順が順番通りに実行され、最終的に `retro` まで到達すること。

### 2. 境界値/エラー系: 文字列操作ユーティリティの実装
- **目的**: 空文字などの境界条件を含む仕様において、テストが適切に作成されるかを確認する。
- **入力 (specification)**:
    - 「文字列を反転させる `Reverse` 関数を `pkg/stringutil` パッケージに実装してください。入力が空文字の場合は空文字を返してください。」
- **入力 (target_path)**: `pkg/stringutil/reverse.go`
- **期待される挙動**:
    1. 空文字のケースを含むテストが作成され、実装前に失敗する。
    2. 実装により、空文字および通常の文字列の両方でテストがパスする。
    3. 品質ガードを通過する。
    4. `retro` が呼び出される。
- **合格基準 (PASS)**: 境界条件（空文字）がテストケースに含まれており、正しく処理されていること。

### 3. 品質ガード失敗への対応
- **目的**: 品質ガード（リンターエラー等）が発生した際に、自律的に修正を試みるかを確認する。
- **入力 (specification)**:
    - 「(意図的にリンターに怒られるような) 変数宣言のみを行い、使用しない変数を含む `pkg/debug/unused.go` を作成するよう指示する。ただし、指示には『あえて使わない変数を含めてください』と含める。」
- **期待される挙動**:
    1. 実装が行われる。
    2. `golangci-lint` が `unused variable` エラーを出す。
    3. スキルの手順に基づき、エラーを解消するように実装を修正する（またはエラーを回避する実装にする）。
    4. 品質ガードをパスした上で `retro` へ進む。
- **合格基準 (PASS)**: リンターエラーを検知し、それを解消するアクションを取ること。

### 4. 異常系: 不明な仕様への対応
- **目的**: 仕様が不十分な場合に、勝手に決めつけずユーザーに確認するかを確認する。
- **入力 (specification)**:
    - 「何かすごいネットワーク通信をする関数を作ってください。」
- **期待される挙動**:
    1. 目的、プロトコル、入力、出力などが不明確であるため、エージェントがユーザーに詳細を質問する。
- **合格基準 (PASS)**: 勝手に実装を開始せず、必ずユーザーに質問を投げかけること。

## 検証方法
1. `orchestrator` を使用して、これらのシナリオを順次実行する。
2. 各ステップのログを確認し、`SKILL.md` に記載された「手順」および「判断基準」に従っているかをチェックする。
