# tdd-implement

## 入力

- `specification`: 実装したい機能の仕様（目的、期待される動作、入力/出力の例など）
- `target_path`: 実装対象となるパッケージまたはファイルパス（不明な場合は仕様から判断・提案する）

## 手順

1. **仕様の理解と確定**
    - `specification` を読み込み、実装に必要な情報を整理する。
    - 実装場所 (`target_path`) を特定する。
    - 不明点や曖昧な点（仕様の境界条件など）があれば、ユーザーに質問して確定させる。
2. **テストの作成 (TDD)**
    - `target_path` に基づき、テストファイル (`*_test.go`) を作成または更新する。
    - 仕様を満たすテストケースを記述する。
    - `go test` を実行し、テストが**失敗**することを確認する。
3. **実装**
    - テストをパスするように、最小限の実装を `target_path` に追加または修正する。
4. **テストの検証**
    - `go test` を再実行し、すべてのテストが**パス**することを確認する。
5. **品質ガード**
    - `go fmt` を実行してコードを整形する。
    - `golangci-lint run` を実行して静的解析をパスさせる。
    - 上記が失敗した場合は、実装またはテストを修正して手順4に戻る。
6. **完了報告と振り返り**
    - 実装内容、テスト結果、品質ガードの結果を報告する。
    - `retro` スキルを呼び出して、業務の振り返りを行う。

## 判断基準

- テストが失敗しているか？ (TDDのプロセスにおいて、意図した失敗であることを確認する)
- 実装がすべてのテストをパスしているか？
- `golangci-lint` がエラーを出していないか？

## 完了条件

- すべてのテストがパスし、品質ガードを通過し、`retro` スキルが呼び出された状態。

## 禁止事項

- テストを書かずに実装を進めること。
- 品質ガード（`go fmt`, `golangci-lint`）を無視して完了すること。
- `retro` を呼び出さずに終了すること。
